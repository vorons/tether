# tether — design doc

**Версия:** 0.1.0 (MVP) · **Лицензия:** MIT

## 1. Цели

Терминальный кодинг-агент с интерактивным TUI, аналог Claude Code и Codex, реализованный на Lua. Один бинарник без внешних runtime-зависимостей, кроме `libc` и `libm`. Работа в workspace, инструменты чтения/записи/поиска/shell/patch, стриминг ответа модели, подтверждения опасных действий, возобновляемые сессии.

## 2. Не-цели MVP

- Вкладки, мультисессии, плагины, векторная память, in-app drag-selection.
- Интерактивный PTY, фоновые задачи, git-интеграция, LSP.
- Windows вне WSL.
- Свой токенизатор: бюджет контекста оценивается как `ceil(chars/4)` (§9).

Часть исходных не-целей уже закрыта: провайдеры Anthropic и Gemini (§5, §8)
и темы `ui.theme` (§6.14). Актуальный трекер этапов — `docs/ROADMAP.md`.

## 3. Целевые платформы

Linux x86_64, macOS arm64/x86_64. Терминалы: xterm-256color, tmux, kitty, wezterm, foot, alacritty, Ghostty, Windows Terminal (в WSL).

## 4. Архитектура

```
┌─────────────────────────────────────────────────────────┐
│  C-хост (src/host)                                      │
│  main · term · shell exec (tether.exec)                 │
│  fs primitives · http (vendored libcurl + mbedTLS)      │
│  embed (C-массивы Lua-модулей)                          │
├─────────────────────────────────────────────────────────┤
│  vendored: Lua 5.4.6 · krep · libcurl · mbedTLS · zlib  │
├─────────────────────────────────────────────────────────┤
│  Lua-ядро (src/tether)                                  │
│  app · ui · agent · api · providers · tools · session   │
│  config · context                                       │
└─────────────────────────────────────────────────────────┘
```

C-хост даёт Lua узкий syscall-API: raw mode, `ioctl(TIOCGWINSZ)`, `realpath`, `tether.exec` (единственный шелл-примитив, `/bin/sh -c`), файловые примитивы (`mkdirp`/`fchmod`/`readdir`/`stat`), поиск (krep), HTTP(S) in-process (vendored libcurl + mbedTLS), детект keyboard protocol. Вся логика — на Lua.

## 5. Компоненты

**app** — точка входа, разбор CLI (`--resume/-r`, `--workspace/-w`, `--model/-m`, `--print/-p [prompt]`, `--debug`, `--agents-file <path>` (повторяемый), `--version/-v`), выбор режима TUI (по умолчанию) / print. Полный список флагов — §14.

**config** — загрузка `~/.tether/config.lua`, merge с CLI-флагами, значения по умолчанию.

**ui** — TUI: транскрипт, ввод, footer (одна строка), палитры (command/path/copy/login/resume/model), confirmation-меню, error banner, masked login secret и стриминг. Полноэкранных overlays нет (palette-only). Детали — §6.

**agent** — цикл LLM → tool calls → выполнение → tool results → LLM. Лимит итераций — 50, жёстко (не настраивается); исчерпание лимита — нормальное завершение хода. Системный промпт: канонический coding-agent, переопределяется `system_prompt` в конфиге (строка или путь к файлу) и дополняется `AGENTS.md`/skills (§15.5).

**api** — диспетчер провайдеров (`src/tether/providers/`): `stream(cfg, key, messages, on_event)` и `list_models*()`; три wire-модуля `openai`, `anthropic`, `gemini` + каталог пресетов `providers/catalog.lua` (42 id: alias на wire-модуль либо Tier-B адаптер `azure-openai`, `amazon-bedrock`, `google-vertex`, `cloudflare-ai-gateway`, `radius`, `openai-codex`), выбор по `cfg.provider` (неизвестное значение → warning и `openai`). `header_lines(api_key, ctx)` несёт `{session_id, provider, messages, url, body, auth_style, provider_env, cfg}` для per-preset заголовков (`x-opencode-session`, Copilot, `cf-aig-authorization`); attribution-заголовки не шлются. Канонические события: `text_delta`, `reasoning_delta`, `tool_call_start`, `tool_call_delta`, `usage`, `retry`, `error`, `done`; агент добавляет свои — `confirmation`, `aborted`, `context_compressed`. Набор событий одинаков для всех провайдеров, поэтому `agent.lua` не ветвится по провайдеру. OpenAI-адаптер маппит `reasoning_summary` на reasoning-события; модели без reasoning их не шлют. Пресеты резолвят модели только live через `/models` (static fallback пуст); Bedrock ходит нестриминговым Converse (eventstream несовместим с построчным транспортом) с SigV4 на чистом Lua.

**tools** — read, write, list, glob, grep, run, patch (§7).

**session** — JSONL-журнал, автосохранение, возобновление по `-r` (§10).

## 6. TUI

### 6.1 Регионы экрана

```
┌──────────────────────────────────────────────────────────────┐
│ transcript (flex, скроллится; виртуализированный)            │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ error banner (1 строка, только при ошибке)                   │
├──────────────────────────────────────────────────────────────┤
│ input (1..8 строк, растёт вверх)                             │
├──────────────────────────────────────────────────────────────┤
│ palette (0..10 строк: окно ≤8 + индикатор)                   │
├──────────────────────────────────────────────────────────────┤
│ separator (1 строка, dim rule между вводом и статусом)       │
├──────────────────────────────────────────────────────────────┤
│ status line (1 строка)                                       │
└──────────────────────────────────────────────────────────────┘
```

Header отсутствует (`ui.header = false`). Полноэкранных overlays нет:
единственный модальный механизм — палитра под вводом (`palette_mode`:
command / path / copy / login / resume / model) и confirmation-меню
(синтетическая строка в хвосте транскрипта). `Esc` закрывает активную
палитру/меню. Секрет `/login` — отдельный masked-буфер (`S.login_secret`),
не overlay. Команды `/help`, `/status`, `/log` удалены в M9 — привязки `?`
больше нет.

Строки распределяются снизу вверх: футер (ввод + разделитель + статус, а также
палитра и баннер ошибки) резервируется от низа экрана, остальное получает
транскрипт (§6.7). Alt-screen включён по умолчанию (`ui.alt_screen = true`) —
TUI перерисовывается в альтернативном буфере и скроллбек оболочки переживает
сессию; `false` возвращает отрисовку на месте.

### 6.3 Блоки транскрипта

Каждый блок — gutter (1–2 символа) + содержимое с висячим отступом.

Вертикальные промежутки (`ui.block_gap`, дефолт 1, `0` — компактный вид):
одна (или `block_gap`) пустая строка перед топ-уровневыми сущностями —
separator, user, assistant, system; строки инструментов и thinking остаются
приклеенными к своему контексту. Промежутка нет: перед первой сущностью
транскрипта, между separator и user-строкой, которой он предшествует, и
перед виртуальными хвостами (confirmation/ask — они несут собственную
ведущую пустую строку). Пустые записи (assistant без текста) промежуток не
получают.

| Тип | Gutter | Цвет | Правила |
|---|---|---|---|
| user | `›` | cyan bold | Перенос с отступом 2 |
| assistant text | `●` | default | Markdown-lite (§6.4) |
| reasoning | `✻ thinking` | dim italic | `ui.thinking = "collapsed"` (дефолт) — одна строка `✻ thinking ▸ (Ctrl+T)`; любое другое значение (в т.ч. `expanded`) — `✻ thinking ▾` и тело блока. `Ctrl+T` — тумблер |
| tool | `✓ <name>` | ✓ зелёный, name accent | Одна строка `✓ <name>  <сводка>` (сводка dim, §6.5); тело скрыто, пока не раскрыто. `write`/`patch` несут в сводке `+N −M` и пропорциональный метр (`━━━━`, ASCII `#`), `write` — слово «создан»/«перезаписан» |
| tool (выполняется) | `… <name>` | dim | `… <name>  <секунды>s`; у `write`/`patch` с доступной проекцией показывает превью изменения за раскрытием (§6.5) |
| tool error | `✗ <name>` | red | Первая строка ошибки приклеена к строке и обрезана по ширине (строка не переносится); полное тело — за раскрытием |
| tool body (diff) | внутри тела | add green, remove red | Тело `write`/`patch` — unified diff: gutter старых/новых номеров, роли add/remove/context, подсветка по языку целевого пути; у парных строк изменённые слова сохраняют роль, перенесённые — dim (§6.5) |
| confirmation | `⚠ <label>` | yellow | `⚠ <name> <path|command>`, тело (diff или команда) и меню `[1/y]`…`[5/Esc]`; выбранный пункт — reverse video |
| diff | внутри confirmation | +/- | Unified diff, рамка `┌│└`; отдельного блока в транскрипте нет (транскрипт использует тот же разбор, §6.5) |
| summary marker | `── summary ──` | dim | Системная строка после `/compact` и автосжатия контекста |
| error banner | `!` | red bg | Одна строка над вводом; `Enter`/`Esc` очищает баннер (без modal-вида); полный текст — в debug-лог при `--debug` |
| resume banner | `↻` | dim | «↻ сессия `<id[:8]>` возобновлена» |
| turn separator | `── HH:MM ──` | dim | Перед каждой новой репликой пользователя (`ui.turn_separators`) |
| streaming placeholder | `✻ tether думает…` | dim | Спиннер в хвосте строки до первого токена (§6.6) |
| streaming caret | `▌` | default | В конце новейшей строки, пока идут дельты; нет при прокрутке вверх и когда палитра/confirmation/ask/secret владеют клавиатурой |

### 6.4 Markdown-lite

Разбираются: инлайн-код (`` ` ``), жирный (`**`), курсив (`*`), fenced-блоки
(``` ```, рамка из box-drawing рамкой в dim — метка языка остаётся читаемой,
soft-wrap внутри рамки, подсветка по языку; имя в fence регистронезависимо,
может нести хвостовые атрибуты (например, ```` ```python title=… ````), первый токен — язык),
заголовки (`#`+; переносятся по ширине, окрашены ролью `heading`, без
автоматической пустой строки после), нумерованные (`1. `) и маркированные
(`-`/`*` → `•`, в ASCII `-`) списки с двухколоночным префиксом и продолжением
в 2 колонки, а также таблицы (строки, начинающиеся с `|`: колонки
выравниваются влево по самой широкой ячейке, строка-разделитель рисуется
dim-линейкой, блок обрезается по ширине терминала). `\`` и `\*` экранируют
маркер. Серии пустых строк в исходнике схлопываются в одну; ведущие и
завершающие пустые строки отбрасываются.

Инлайн-маркеры снимаются и окрашиваются ролями темы (`code`, `bold`,
`italic`) через `ansi_fn` (`M.md_ansi`) — передаётся в `md_render` из тела
ассистента и описания ask-блоков. HTML, ссылки и картинки не разбираются —
такие строки идут обычным текстом.

### 6.5 Скрытие и раскрытие результатов

**Правило.** Тела результатов скрыты по умолчанию у **всех** инструментов
(`read`, `list`, `glob`, `grep`, `run`, `write`, `patch`) — в транскрипте видна
только строка инструмента со сводкой. Ошибки, как и раньше, видны без
раскрытия, но только первой строкой (обрезанной по ширине строки); полный
текст ошибки — за раскрытием.

**Статус строки.** Впереди — маркер состояния: `✓` (успех, ASCII `[ok]`),
`✗` (ошибка, ASCII `[x]`), `…` (выполняется). Сводка идёт после имени.

**Краткая сводка** в хвосте строки инструмента:

| Инструмент | Сводка |
|---|---|
| `read` | `<N> стр.` |
| `list` | `<N> записей` |
| `glob` | `<N> файлов` |
| `grep` | `<N> совп.` |
| `run` | `exit <code>`, `<time>` |
| `write` | `+<N> −<M>` + «создан»/«перезаписан» |
| `patch` | `+<N> −<M>` |

`write`/`patch` добавляют к сводке пропорциональный метр (`━━━━`; ASCII `#`),
где каждой ненулевой стороне достаётся хотя бы один блок, а соотношение
N:M сохраняется с точностью до блока. Если прежнее содержимое не прочитано
(см. ниже), `write` падает обратно на `+<bytes> B` без счётчиков diff.

**`run`** скрывает stdout и stderr целиком; в строке только `exit <code>` и время.

**Тела инструментов.** Раскрытые тела рендерятся так:

- `read`/`grep` подсвечиваются тем же токенайзером, что и fenced-блоки, по
  языку целевого пути (`.lua`→lua, `.c`/`.h`→c, `.sh`/`.bash`→sh, `.py`→python,
  `.js`/`.ts`→js, `.go`→go, `.rs`→rust, `.json`→json). `lineno<TAB>`-префикс
  `read` и `path:line:`-префикс `grep` остаются вне подсветки; `list`, `glob` и
  `run` рендерятся без подсветки. `ui.highlight = "off"`, ASCII и тема без
  цвета снимают подсветку.
- `write`/`patch` рендерятся как unified diff: gutter старых/новых номеров,
  роли add/remove/context (зелёный/красный/обычный), подсветка содержимого по
  языку целевого пути, заголовки файла/ханка. Тело, не разбирающееся как diff,
  показывается обычным текстом. У парных строк (одинаковой длины) изменённые
  слова сохраняют роль add/remove, а перенесённые рисуются dim; тема без цвета
  рендерит diff без пословного акцента.
- Перед выводом убираются управляющие последовательности, кроме SGR: движения
  курсора, erase-последовательности, `\r` и OSC/DCS (в т.ч. смена заголовка
  окна) не доходят до строк; серии пустых строк сворачиваются в одну. Это
  только display: тело для модели, журнала и `/copy` остаётся исходным. SGR
  сохраняется пока цвет включён и снимается вместе со всем остальным при
  `NO_COLOR`/ASCII/`mono`.

**Проекция до выполнения.** Пока `write`/`patch` ещё выполняются, агент
присылает на `tool_call_start` read-only проекцию изменения (только внутри
workspace, файл не больше 1 MiB, без записи и без истории). Строка показывает
её превью за раскрытием; после выполнения превью замещается результатом, а при
отказе/отмене/прерывании — убирается. Если проекцию получить нельзя, строка
остаётся обычной.

**Раскрытие.** Состояние раскрытия — per-entry (`expanded`/`collapsed`),
перекрывающее общий флаг (по умолчанию свёрнуто), либо унаследованное от
общего флага. Управление:

- левый клик по строке инструмента переключает эту запись — в режиме мыши
  `ui.mouse = "on"` (в `auto`/`off`/`selection` транскрипт-клики не приходят);
- `Ctrl+O` переключает новейшую запись инструмента, пересекающую видимую
  область (при отсутствии такой — новейшую в транскрипте);
- `Ctrl+Shift+O` переключает все записи разом и стирает per-entry состояние;
- на терминалах без модификатора Shift (протокол не определён) `Ctrl+O`
  сохраняет прежний смысл «раскрыть/свернуть все».

Состояние раскрытия не сохраняется между сессиями и не уходит агенту. При
раскрытии длинные тела обрезаются по `ui.collapse = {read = 20, list = 30,
  grep = 15}` (для инструментов без порога — 200 строк), остаток сообщается
строкой `… (N строк скрыто)`.

### 6.6 Стриминг

```
 ● Цикл устроен так: LLM возвращает tool calls, я выполняю их в
   workspace и отправляю результаты обратно. Повторяется до▌

   ✻ tether думает… ⠋
```

- После `Enter` сразу рисуется плейсхолдер `✻ tether думает…` со спиннером (`⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`; ASCII `| / - \`) в хвосте транскрипта, а статус-строка ведёт спиннер с секундами: `⠋ 3s`.
- Плейсхолдер исчезает с первым `text_delta`/`reasoning_delta`; вместо него в конце
  новейшей строки появляется каретка `▌` (ASCII `|`). Ни плейсхолдер, ни каретка
  не рисуются, если пользователь прокручен вверх или когда палитра /
  confirmation / ask / secret владеют клавиатурой.
- Перерисовка идёт по дельтам (с троттлингом) и немедленно — на переходах: старт
  tool call, результат, ошибка, abort, confirmation.
- `Ctrl+C` при активном ходе прерывает стрим и сохраняет уже полученный текст;
  вне хода первый `Ctrl+C` очищает ввод, второй в течение 1 с — выход.
  ('aborted' не пишется в мета сессии — см. §10.)
- Автоскролл вниз, пока пользователь не прокрутил вверх; после ручной прокрутки —
  индикатор `↓ +N` на footer-строке (§6.6b/§6.13),
  `End` возвращает к низу.

### 6.6a Ключи UI-конфига

- `ui.highlight = "auto"` — подсветка синтаксиса в fenced code blocks:
  lua, c/h, sh/bash, python, js/ts, go, rust, json (имя языка в fence —
  регистронезависимо). При `auto` подсветка включена, когда цвет есть
  (`color_depth ~= "none"`, т.е. 256/truecolor); ASCII, `NO_COLOR=1` и
  `TERM=dumb` дают `none` и выключают её; `"off"`/`"on"` — принудительно.
- `ui.turn_separators = true` — dim-строка `── HH:MM ──` перед каждой новой
  репликой пользователя; `false` скрывает их. Восстановленные сессии
  (`-r`, `/resume`) разделителей не получают.
- `ui.block_gap = 1` — число пустых строк перед топ-уровневыми сущностями
  транскрипта (§6.3); `0` — компактный вид без промежутков.
- `ui.path_completion = true` — `Tab` вне палитры дополняет токен под
  курсором до пути относительно workspace (лидирующий `@` не обязателен и
  сохраняется в вводе); `false` отключает.

### 6.6b Индикатор строк ниже при прокрутке вверх

Пока пользователь прокручен вверх (не в follow-режиме), footer-строка
показывает, сколько строк транскрипта скрыто ниже: `↓ +N` (ASCII `v +N`)
рядом с toast (§6.13). Индикатор не рисуется, когда скрытых строк нет.
Возврат к низу (`End`, `↓` до конца, колесо вниз) снова включает
follow-режим и убирает индикатор.

### 6.7 Поле ввода

```
 › первая строка ввода█
   вторая строка, отступ 2
──────────────────────────────────────────────────────────────
 ~/proj/tether ↑3.0k ↓1.0k 4.1k/32k (13%)                    gpt-4o-mini
```

- Префикс `› ` только у первой строки; продолжения — отступ 2.
- Растёт вверх до `ui.input_max_lines = 8`, дальше скроллится внутри себя.
- Под полем ввода — dim-разделитель `─` на всю ширину (1 строка; в ASCII `-`), под ним footer (§6.13). Разделитель есть всегда, в том числе при однострочном вводе.
- Над верхним разделителем — одна пустая строка-зазор между транскриптом и рамкой поля ввода.
- Бюджет футера резервируется снизу вверх, до раздачи строк транскрипту: `input_h + palette_h + error_h + 1` (зазор над рамкой) `+ 1` (разделитель) `+ 1` (footer), где `input_h` — число видимых строк ввода (`min(строк, ui.input_max_lines)`, но не меньше 1), `error_h` = 1 при видимом баннере ошибки, `palette_h` = 0 без палитры. Транскрипт получает все остальные строки, поэтому строки ввода строго выше разделителя, разделитель — строго выше footer, и регионы никогда не перекрываются: рост ввода на 1 строку уменьшает транскрипт ровно на 1 строку.
- `Enter` — отправить; `Ctrl+J` — новая строка; `Shift+Enter` — новая строка при Kitty/modifyOtherKeys.
- `↑`/`↓` — история ввода (§6.12); в многострочном вводе — перемещение курсора по строкам, `Shift+↑`/`Shift+↓` — явное перемещение. Прокрутка транскрипта — `PgUp`/`PgDn`. `Ctrl+↑`/`Ctrl+↓` — тоже история.
- `Ctrl+A/E/U/W/K` — readline-подобные.
- `Ctrl+V` — bracketed paste; многострочная вставка сохраняет переводы строк.
- Ввод блокируется при открытом confirmation и на время выполнения инструмента без стрима.

### 6.8 Слэш-команды и палитра

Палитра открывается, когда первая непробельная последовательность в первой
строке ввода начинается с `/`. Список один: команды
`/clear /compact /model /resume /new /quit /copy` в объявленном порядке, затем
навыки из discovery (§15.5) строками `/имя` в порядке обнаружения. Навык, имя
которого совпадает с именем команды без учёта регистра, не листится: токен
принадлежит команде. Фильтр — регистронезависимая подпоследовательность по
имени записи, совпадения по префиксу идут выше; пустой фильтр показывает все
записи в этом порядке (сначала команды, затем навыки), совпадение по префиксу
в любой из групп выигрывает у совпадения внутри. Строка несёт имя, описание и
— сразу после имени — подсказку аргументов, если запись её объявляет: у навыка
это `[skill]`, команды подсказок не объявляют, потому что аргументов не
принимают. Колонка имени выравнивается по самой длинной паре имя+подсказка
среди всех записей, поэтому описания команд и навыков стартуют в одной
колонке. Рамки нет: выбранная строка подсвечена акцентом, остальные dim.

Окно прокрутки — `min(8, floor(h/2))` строк, но не меньше одной, со сдвигом,
удерживающим выделенную строку внутри; записи вне окна не рисуются. Когда
записей больше окна, на свободной строке региона рисуется dim-индикатор
`sel/total` (только цифры и `/`); если эта строка не помещается в регион,
индикатор не рисуется, окно записей не сжимается под него, и палитра не
заходит ни на разделитель, ни на footer.

`↑↓` — навигация, `Enter` — выполнить команду либо, для строки навыка, только
дописать `/<имя> ` в ввод и закрыть палитру (ничего не выполняется, тело
`SKILL.md` не читается и в транскрипт не попадает), `Tab` — дополнить имя в
ввод, `Esc` — закрыть палитру, оставив набранный текст. Палитра закрывается,
если в фильтре появился пробел или первый символ больше не `/`. Навыки
разрешаются один раз при открытии палитры, а не на каждое нажатие; сбой
discovery деградирует к списку команд. Клик мыши по строке палитры резолвится
через смещение окна, клик по индикатору не выбирает ничего.

```
 › /mo█
  /model     сменить модель
```

Команды `/help`, `/status`, `/log` и их отдельные view удалены в M9.

Поведение:

- `/clear` — очищает транскрипт в памяти; подтверждения нет; сессия на диске не трогается, агент сохраняет всю историю.
- `/compact` — принудительное сжатие старых сообщений; в транскрипт добавляется системная строка со сводкой (заголовок `── summary ──`).
- `/model` — палитра со списком моделей (`palette_mode = "model"`): модели всех провайдеров с ключами (активный первым, строки с тегом провайдера) из свежего дискового кэша мгновенно, протухшие — фоном; выбор чужой модели переключает провайдера сессии и перерезолвит ключ; без ключей — пусто с подсказкой `/login`.
- `/resume` — палитра последних сессий текущего workspace (`palette_mode = "resume"`, §6.9); то же делает `Ctrl+R`.
- `/new` — новая сессия; старая остаётся на диске с `session_end`; транскрипт и история агента сбрасываются.
- `/quit` — выход; как `Ctrl+Q` / двойной `Ctrl+C`; подтверждения при активном стриме нет.
- `/copy` — палитра целей (последний ответ, последний вывод инструмента, последний код-блок, весь транскрипт), в каждой строке — имя и размер в байтах; `Enter` копирует через OSC 52 и показывает toast `✓ скопировано <bytes> B`, `Esc` закрывает без копирования.
- Навыки — отдельной команды нет: они листятся в общей палитре (§15.5). Отправка `/<имя>`, совпавшего с обнаруженным навыком, уходит агенту обычным сообщением — текст дословно, включая префикс, — и команда при этом не выполняется; сравнение имён идёт без учёта регистра на обеих проверках, поэтому `/CLEAR` выполняет `/clear`, а `/COPY` при обнаруженном навыке `copy` выполняет команду. Имя, не совпавшее ни с командой, ни с навыком, агенту не отправляется.

`Enter` при открытой палитре выполняет команду, а не отправляет сообщение; для
строки навыка `Enter` только дописывает имя в ввод.

### 6.9 Resume palette

Палитра под вводом (`palette_mode = "resume"`), строки формата
`<HH:MM> · <id[:8]> · <первая строка пользователя, до 40 символов>`,
выбранная — reverse video (механика окна и индикатора — как у `/copy`,
§6.8). Полноэкранный overlay не используется.

```
 › /resume
  14:32 · a1b2c3d4 · добавь тесты для glob
  13:07 · e5f6a7b8 · объясни структуру проекта
```

Сортировка по mtime, только сессии текущего workspace, до 100 файлов. `Enter`
возобновляет выбранную сессию и **заменяет** видимый транскрипт (с маркером
`↻ сессия … возобновлена`), `↑↓` — навигация, `Esc` — закрыть. Быстрый вход —
`Ctrl+R`.

### 6.10 Confirmation-меню

Меню появляется, когда инструмент требует подтверждения (`write`, `patch`, `run`,
когда `allow_outside_workspace = false` и цель/`cwd` уходит за пределы
workspace). Это не overlay, а строка в хвосте транскрипта: она заменяет собой
плейсхолдер хода и блокирует ввод.

```
 ⚠ patch src/tether/agent.lua
   ┌ a/src/tether/agent.lua
   │ @@ -40,6 +40,8 @@
   │  local function on_event(ev)
   │ +  if ev.tool_call_start then
   │ +    calls[#calls+1] = ev
   │    table.insert(calls, ev)
   └──────────────────────────────────────────────
   [1/y] once     разрешить один раз
   [2/a] session  разрешить до конца сессии
   [3/A] always   сохранить в auto_approve
   [4/n] deny     отклонить
   [5/Esc] cancel прервать ход агента
```

- Навигация `↑↓` + `Enter`; цифры `1..5` и буквы `y/a/A/n` работают сразу (`Esc` = cancel).
- Выбранный пункт — reverse video (маркера `›` нет).
- Тело меню: patch — unified diff; run — команда и `cwd=` при наличии плюс строка `⚠ потенциально опасная команда`, если сработал детектор (`rm -rf`, `sudo`, `curl | sh`, `mkfs`, `dd`, `> /`, fork bomb); write — `write → <path> (N B)`.
- `[3/A] always` пишет anchored-паттерн в `~/.tether/auto_approve.lua`; подменю «что именно сохранять» нет. Файл подхватывается при следующем `config.load` — постоянное разрешение переживает перезапуск.
- Опции `details` / клавиши `[d]` нет: полный projected diff — на pending tool-строке транскрипта (§6.5), тело результата — за раскрытием.
- `[5/Esc] cancel` отклоняет все вызовы очереди (`cancelled by user`).

### 6.12 История ввода

`~/.tether/history.jsonl`, по строке на запись:

```json
{"ts":"...","workspace":"/abs/path","text":"..."}
```

Запись добавляется при отправке сообщения агенту; файл один на машину и не
обрезается. В памяти TUI держатся последние 200 записей текущего workspace (без
подряд идущих дублей) — их и листают `↑` / `↓` (и `Ctrl+↑` / `Ctrl+↓`):
`↑` открывает новейшую запись, `↓` ниже новейшей очищает ввод. Внутри
многострочного ввода `↑`/`↓` перемещают курсор по строкам, историю они
подмешивают только на границе многострочности; явное перемещение —
`Shift+↑`/`Shift+↓`. Прокрутка транскрипта — на `PgUp`/`PgDn` (§6.7).

### 6.13 Footer (одна строка)

```
 ~/proj/tether ↑3.0k ↓1.0k 4.1k/32k (13%)                    gpt-4o-mini
```

Одна dim-строка под боксом. Слева направо, через один пробел: workspace
(`$HOME` → `~`), счётчики `↑N`/`↓N` (каждый опущен, пока 0), context cell
`used/max (pct%)`, transient-флаги (toast, `↓ +N`); model name — справа с
отступом ≥2 колонок. При нехватке ширины model обрезается слева (хвост
выживает) и опускается, если не помещается совсем; затем path → toast →
scroll → stats. Reverse video не используется. В ASCII — только `^`/`v`.

1. **toast** — `✓ скопировано <bytes> B`; снимается любым нажатием, без таймера.
2. **scroll** — `↓ +N` / `v +N`, только когда пользователь прокручен вверх (§6.6b); единственный индикатор позиции (in-transcript marker убран).
3. **model**.

Иконки режима мыши (`🖱`) и клавиатурного протокола (`⌨`) убраны; трекинг
мышью/протокола продолжает работать без отображения.

### 6.14 Цвета и темы (тема `default`)

| Роль | Атрибут |
|---|---|
| accent / user gutter | cyan bold |
| assistant gutter | без SGR (default) |
| thinking | dim italic |
| tool name | accent |
| tool error / error banner | red |
| diff add / remove | green / red |
| diff context | dim |
| status line | reverse |
| selection (меню, палитра) | reverse |
| inline code / markdown-заголовки | magenta (код), cyan bold (заголовок) — роли `code` / `heading` |
| подсветка кода: comment / string / number / keyword | dim / green / yellow / cyan bold |

`ui.theme` выбирает тему: `default`, `solarized`, `mono` (неизвестное значение →
`default`). Все роли интерфейса — от гуттеров и флагов до палитры и подсветки
кода — идут через таблицу темы (`sgr_role`), поэтому смена темы перекрашивает
весь TUI, а `mono` (пустая таблица) не выводит ни одной SGR-последовательности.
Глубина цвета из `COLORTERM`: `truecolor`/`24bit` → 24-битные SGR, иначе
256-цветные; `ui.highlight = "off"` или ASCII/`NO_COLOR`/`TERM=dumb` → без SGR
вообще.

`ui.ascii = "auto" | "on" | "off"` (по умолчанию `auto`); legacy-булевны
`true`/`false` равнозначны `"on"`/`"off"` и продолжают работать. При `auto`
ASCII включается по окружению: `NO_COLOR=1` или `TERM=dumb`. В ASCII-режиме
глифы заменяются (`›`→`>`, `●`→`*`, `─`→`-`, `⚙`→`[t]`, `✻`→`*`, `⚠`→`!`, `↓`→`v`,
`↑`→`^`, `▌`→`|`) и ANSI-последовательности не выводятся.

### 6.15 Устойчивость

- `SIGWINCH` — пересчёт размеров, перерисовка из кэша транскрипта.
- Транскрипт виртуализирован: построчный дифф, кэш перенесённых строк на запись и префиксная сумма высот, поэтому перерисовка и кэш ограничены видимой областью, а не длиной сессии (см. спеку `tui`).
- При выходе — восстановление termios, `CSI ? 25 h`, выключение mouse reporting и bracketed paste, выход из alt-screen, если он был включён.
- Паника в C-хосте — `atexit` восстанавливает терминал.

## 7. Инструменты

| Имя | Аргументы | Поведение |
|---|---|---|
| `read` | `path, offset?, limit?` | 1 MiB максимум; бинарные (NUL в первых 8 KiB) отклоняются; до 200 000 строк; `offset` = 1, `limit` = 10000; строки вывода — `lineno<TAB>content` |
| `write` | `path, content` | Атомарно: временный файл рядом + `rename`; возвращает `{bytes, path}`; подтверждение вне workspace |
| `list` | `path?` | Сортированный список каталога (in-process `tether.readdir`), по умолчанию корень workspace; возвращает `{entries, count}` |
| `glob` | `pattern, path?` | `*`, `**`, `?`, `[abc]`, `[!abc]`; матч по относительному пути или basename; сортировка; лимит 500 |
| `grep` | `pattern, path?, glob?, ignore_case?, max_results?` | Vendor'd `krep` in-process (POSIX ERE; учитывает `.gitignore`, `glob`, `ignore_case`); формат `{path, line, column, text}`, `column` всегда 1; `max_results` = 100 |
| `run` | `command, cwd?, timeout?` | `cd <cwd> && timeout <s> env TETHER_WORKSPACE=<cwd> sh -c <cmd>`; timeout 120 с; вывод во временный файл, возвращает `{output, exit_code, elapsed_ms}` |
| `patch` | `patch` | Unified diff, путь из `b/` при наличии, хунки применяются от последнего к первому; при расхождении — `patch conflict in <file> — перечитайте файл`, файл не меняется |

Все пути относительно workspace, если не абсолютные. Workspace = `cfg.workspace`
(или `TETHER_WORKSPACE`), иначе cwd; приводится к `realpath`, symlink-и
раскрываются. `write`, `patch` и `run` вне workspace сам инструмент
**отклоняет** с ошибкой `... outside workspace requires confirmation` — разовое
разрешение выдаёт меню подтверждения агента (§6.10), а
`allow_outside_workspace = true` — постоянный обход.

## 8. Terminal I/O

**Keyboard.** `ui.keyboard_protocol = "auto" | "kitty" | "modifyOtherKeys"`;
любое другое значение — `plain` (без протокола). При старте `auto`
определяет терминал ($TERM_PROGRAM/`TERM`): Kitty, VTE/alacritty/xterm — иначе
остаётся legacy-ввод и fallback `Ctrl+J` для новой строки.

Определённый протокол **включается** на время сессии и снимается на выходе,
поэтому терминал остаётся в исходном режиме: kitty — push `CSI > 1 u`
после входа в alt-screen и pop `CSI < u` перед выходом из него (у kitty
свой стек флагов на каждый экран); xterm-подобные — `CSI > 4 ; 2 m` и
`CSI > 4 ; 0 m`. Ввод разбирается в одном месте: legacy-байты, kitty
`CSI <code> ; <mods> u` (модификаторы — битовая маска + 1) и xterm
`CSI 27 ; <mods> ; <code> ~` дают одно и то же представление клавиши. Поэтому
`Shift+Enter`/`Ctrl+Enter` вставляют новую строку, `Ctrl+Shift+C` копирует
последний ответ, `↑`/`↓` и `Ctrl+↑`/`Ctrl+↓` листают историю, а `Esc` больше не
путается с началом escape-последовательности. Определённый протокол больше не
отображается в footer (`⌨ kitty` / `⌨ xterm` убраны), но по-прежнему
включает модификатор Shift для `Ctrl+Shift+O` (§6.5).

**Mouse.** `ui.mouse = "auto" | "on" | "off" | "selection"`. SGR mouse
(`CSI ? 1006 h` + `CSI ? 1000 h`), включается только при смене состояния.
`auto` (дефолт) — трекинг включён постоянно: колесо должно прокручивать
транскрипт. Без перехвата терминалы (kitty, iTerm, Windows Terminal)
преобразуют колесо в стрелки ↑/↓ — а те теперь листают историю ввода, так что
тик колеса вставлял историю в поле. Нативное выделение текста — через
`Shift+мышь` (или `ui.mouse = "selection"`). `on` — всегда; `off` и
`selection` — никогда. Колесо вверх прокручивает к старым строкам (`S.scroll`
растёт), вниз — к низу (при `S.scroll = 0` — follow-режим); клик выбирает
пункт меню/палитры. In-app drag-selection отсутствует (отдельного ключа
`ui.mouse_selection` нет).

**Clipboard.** OSC 52 (`ESC ] 52 ; c ; <base64> BEL`) без внешних утилит
(`pbcopy`/`xclip`/`wl-copy` не вызываются). `Ctrl+Shift+C` — копировать
последний ответ ассистента, `/copy` — палитра целей (§6.8). В буфер попадает
текст без ANSI-последовательностей.

## 9. Потоки данных

**Стриминг чата.** `agent` формирует запрос → `api.stream` → C-хост выполняет запрос in-process (vendored libcurl + mbedTLS, без субпроцесса) и отдаёт тело построчно в Lua через `on_line` → `api.lua` парсит SSE → канонические события → `ui` обновляет транскрипт.

**Tool-call.** LLM возвращает `tool_call` → агент проверяет политику (workspace/подтверждение) → `tools.*` выполняет → результат как `tool_result` → следующий запрос LLM.

**Сжатие контекста.** Бюджет — `context.max_tokens` (по умолчанию 32768),
порог — `context.summarize_at` (0.7), а оценка —
`ceil(сумма длин содержимого / 4)`. Когда оценка превышает
`summarize_at × max_tokens`, агент оставляет системный промпт и последние 4
сообщения (отступая назад, если на границе оказался `tool`-результат, — чтобы он
не оторвался от своего `tool_call`), а всё старое заменяет одним системным
сообщением `── summary ──` со списком старых сообщений, обрезанных до 200
символов каждое, и шлёт в UI `context_compressed`. Отдельного вызова модели для
суммаризации и резерва «на ответ» нет (`/compact` вызывает тот же код).

**Ретраи API.** До `cfg.retries` попыток (по умолчанию 3) с задержкой
0.5/1/2 с. Повтор — если тело пустое, статус 429 или >= 500 либо текст тела
похож на rate-limit/server-error; успешный SSE (тело с `data:`) не
повторяется; прочие 4xx — без повторов; `Retry-After`/`retry_after` из тела
имеет приоритет над расписанием. После исчерпания — событие `error`
(`API failed after <N> attempts: <reason>`) и сообщение в TUI.

## 10. Схемы данных

**Сессия** (`~/.tether/sessions/<id>.jsonl`), по строке на событие:

```json
{"ts": "...", "type": "session_start|message|tool_call|tool_result|summary|session_end",
 "role?": "...", "content?": "...", "tool_calls?": [...], "tool_call_id?": "...",
 "name?": "...", "args?": {...}, "result?": {...},
 "meta?": {"workspace": "/abs/path", "model": "..."}}
```

`tool_result` несёт `{tool_call_id, name, result}`, где `result` — это `{error}`
или `{summary}` (одна строка), а не полное тело. `session_start` пишется первым
событием с `meta.{workspace, model}`, `session_end` — последним. Флаг abort в
`meta` не пишется: `session_end` несёт только `{workspace, model}`.

`-r` выбирает последнюю сессию по mtime среди файлов с совпадающим
`meta.workspace` (сверяется первое и последнее событие файла) и
восстанавливает последовательность сообщений; при отсутствии совпадений
сообщает и стартует новую. `/resume` показывает до 100 последних файлов
(`{id, mtime, ts, first_line}`), где `first_line` — первое user-сообщение.

**config.lua** (`~/.tether/config.lua`):

```lua
return {
  provider = "openai",
  api_key_env = "OPENAI_API_KEY",
  base_url = "https://api.openai.com/v1",
  model = "gpt-4o-mini",
  workspace = nil,
  allow_outside_workspace = false,
  auto_approve = {},
  providers = {                     -- per-provider api_key_env/base_url/model,
                                    -- дефолты из providers/catalog.lua (42 id)
    openai    = { api_key_env = "OPENAI_API_KEY", base_url = "https://api.openai.com/v1" },
    anthropic = { api_key_env = "ANTHROPIC_API_KEY", base_url = "https://api.anthropic.com",
                  model = "claude-sonnet-4-20250514" },
    gemini    = { api_key_env = "GEMINI_API_KEY",
                  base_url = "https://generativelanguage.googleapis.com",
                  model = "gemini-2.5-flash" },
    -- deepseek/groq/cerebras/xai/openrouter/… — см. catalog.lua и README
  },
  context = { max_tokens = 32768, summarize_at = 0.7 },
  retries = 3,
  ui = {
    theme = "default",              -- "default" | "solarized" | "mono"
    header = false,
    keyboard_protocol = "auto",     -- "auto" | "kitty" | "modifyOtherKeys"
    mouse = "auto",                 -- "auto" | "on" | "off" | "selection"
    thinking = "collapsed",         -- "collapsed" (свёрнут) | иначе развёрнут
    ascii = "auto",                 -- "auto" | "on" | "off"
    wrap = true,
    collapse = { read = 20, list = 30, grep = 15 },
    input_max_lines = 8,
    alt_screen = true,
    highlight = "auto",             -- "auto" | "on" | "off"
    turn_separators = true,
    path_completion = true,
  },
  tools = { run_shell = { timeout = 120 } },
  system_prompt = nil,              -- строка или путь к файлу
  skills_dirs = nil,                -- nil = discovery по умолчанию (§15.5)
  agents_files = {},                -- доп. файлы инструкций, до --agents-file
  log_level = "info",
}
```

Ключи `providers`/`base_url`/`model` резолвятся так: `providers[<активный
провайдер>].<ключ>` побеждает, иначе legacy-ключ верхнего уровня (он же и
дефолт `openai`), иначе дефолт провайдера из каталога. Секреты — только через env.
Составные credentials (`auth.provider_env`: Cloudflare account/gateway,
Vertex project/location, AWS-селекторы) мерджатся stored-entry `env` поверх
окружения; `config.api_key` возвращает стиль (`bearer` для OAuth,
`ANTHROPIC_AUTH_TOKEN`, минченных Vertex-токенов) через `cfg._auth_style`.
`ANTHROPIC_OAUTH_TOKEN` резолвится как ключ; Vertex ADC минтится через
`oauth2.googleapis.com/token` (client из ADC-файла); Bedrock ambient chain —
static keys → `AWS_PROFILE`/`~/.aws/credentials` → ECS → IRSA.

## 11. Сборка

```
tether/
  Makefile
  README.md
  LICENSE
  docs/design.md
  vendor/lua-5.4.6/   # единственная vendored-зависимость
  src/host/           # main.c, embed.c (генерируется)
  src/tether/         # app, ui, agent, api, providers/, tools, session,
                      # config, context
  tools/embed.lua     # генератор C-массивов
  tests/
```

`make`: 1) сборка объектных файлов vendored-Lua 5.4.6 (без `luasystem`);
2) сборка вендорных `krep`, `libmbedtls`, `libz` и `libcurl` в `build/`;
3) генерация `src/host/embed.c` из всех `.lua` ядра (`tools/embed.lua`);
4) линковка `tether` со статическими Lua/krep/libcurl/mbedTLS/zlib. Цель —
один бинарник без внешнего Lua-рантайма, luarocks и внешних CLI (только
`libc` + `libm`; см. `ldd ./tether`). `embed.c` перегенерируется при изменении
любого `.lua` или самого генератора. Исходники вендоров лежат в `vendor/`;
ничего не докачивается во время сборки.

**Транспорт HTTPS.** C-хост выполняет запросы in-process через вендорный
libcurl + mbedTLS (потоковая передача тела через write-callback в Lua
`on_line`). Внешний `curl` не нужен; TLS-проверка идёт по системному CA-bundle
(`/etc/ssl/certs/ca-certificates.crt` и аналоги), при его отсутствии запрос
завершается понятной ошибкой.

## 13. Риски

| Риск | Митигация |
|---|---|
| Нет системного CA-bundle для HTTPS | понятная ошибка до начала стрима (`no system CA bundle found`) |
| Терминал не различает Shift+Enter | chain: kitty → modifyOtherKeys → `Ctrl+J` |
| Нет точного токенизатора | `usage` из API или `ceil(chars/4)`; хранить оба |
| Суммаризация искажает контекст | summary как системное сообщение + полный JSONL на диске |
| Различия SSE у провайдеров | канонические события + per-provider модуль |
| Медленный поиск по большому дереву | vendor'd `krep` (SIMD-ускоренный, с Aho-Corasick), in-process |
| Кириллица и широкие символы ломают выравнивание | ширина считается в колонках (`wcwidth`), курсор и переносы по display-width |
| Долгая сессия тормозит перерисовку | виртуализация транскрипта и кэш перенесённых строк (§6.15) |
| Поведение мыши в tmux | документируем `set -g mouse on`; `Shift+мышь` для выделения |

## 14. CLI

```
tether                       интерактивный TUI
tether -r, --resume          возобновить последнюю сессию для текущего проекта
tether -w, --workspace PATH  задать workspace
tether -m, --model NAME      задать модель (текущего провайдера)
tether -p, --print [PROMPT]  неинтерактивный один прогон (иначе промпт из stdin)
tether --agents-file PATH    доп. файл инструкций; флаг повторяемый
tether --debug               подробный лог
tether -v, --version         версия
```

В режиме `-p`: финальный текст — в stdout, трассировка — в stderr, код возврата
0 — успех, 1 — ошибка, пустой ответ или отсутствие промпта; подтверждений нет,
выход за workspace блокируется без `auto_approve`.

## 15. Логи

`--debug`, файл `~/.tether/log/tether.log`, уровень в конфиге. Без секретов и без полного содержимого файлов по умолчанию. Ошибки API — в TUI и лог.

## 15.5 Композиция system prompt (AGENTS.md + skills)

Модуль `context` (`src/tether/context.lua`) собирает system prompt из четырёх
блоков, склеенных `"\n\n"`:

1. База — `system_prompt` из конфига, иначе встроенный `agent.builtin_prompt`.
2. `AGENTS.md` — `$HOME/AGENTS.md` → `<workspace>/AGENTS.md` (нет файла —
   молча; нечитаемый — warning на stderr). Кэп 16 КБ применяется к каждому
   файлу отдельно, при превышении
   обрезается с пометкой `…(truncated)`.
3. Явные agents-файлы — `config.agents_files` (по порядку), затем повторный
   флаг `--agents-file` (по порядку). Непрочитанный путь — warning, обход.
4. Индекс skills — заголовок + строки `name/description/file`.

### Обнаружение skills

Каталоги по умолчанию (first-wins по имени): `~/.tether/skills`,
`<workspace>/.tether/skills`, `~/.agents/skills`,
`<workspace>/.agents/skills`. Список `skills_dirs` в конфиге заменяет их
целиком. Внутри каталога ищутся `*/SKILL.md`; из frontmatter берутся
`name`/`description` (name fallback = имя каталога). В промпт попадает только
индекс; тело `SKILL.md` читается агентом через `read`.

Перечисление подкаталогов — `tether.readdir` (у embedded-хоста нет `io.popen`);
никаких шелл-вызовов `ls`/`find` больше нет.

## 16. Тесты

`make test` состоит из пяти ступеней и падает на любой из них:

1. `luac -p` по всем модулям `src/tether/*.lua` (включая `providers/` и `context`).
2. `tests/lua_tests.lua` — юнит-тесты чистых модулей (JSON, glob, патч, config,
   session, api-парсинг, context) вместе с frame-тестами TUI: подменяется
   `tether.*` и `agent/config/session`, собираются байты, которые ушли в терминал.
3. `tests/context_tests.lua` — составление промпта, AGENTS.md, agents-файлы,
   skills (изолированный `HOME`/workspace через `mktemp`).
4. `tests/context_e2e.sh` — снимает system message через локальный HTTP-stub и
   сравнивает с эталоном; `tests/host_smoke.sh` — smoke C-хоста (raw mode
   включается/выключается, EOF-путь, обработка SIGINT).
5. `tests/host_primitives_test.c` — C-тест хоста: подключает `src/host/main.c`
   с переименованным `main` и проверяет `mkdirp`/`fchmod`/`readdir`/`stat`,
   движок krep (gitignore, glob-фильтр, `max_results`), HTTP-транспорт на
   локальном сервере и отказ TLS-проверки на самоподписанном сертификате
   (`openssl s_server`, проверка пропускается, если нет CLI `openssl`).

Внешних фреймворков нет; симлинк `tether` перед запуском собирается целью `test`.
