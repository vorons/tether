## 3. Критические проблемы (blocker/critical) — СТАТУС

1. ~~**[blocker] SIGCHLD = SIG_IGN**~~ — **ИСПРАВЛЕНО**. `src/host/main.c`:
   `setup_signal_handlers` больше не трогает SIGCHLD; `l_fetch_bg` делает
   double-fork — промежуточный ребёнок `waitpid`-ит внука, внук переходит под
   init, зомби не накапливается. Регрессионный тест: `tether.exec("true")`
   → `ok=true, code=0` в `tests/host_primitives_test.c` (ловит возврат баги).
2. ~~**[critical] Cloudflare partial auth**~~ — **ИСПРАВЛЕНО**. `config.api_key()`
   резолвит `CLOUDFLARE_API_KEY` из `cfg.provider_env` (stored auth.json `env`
   + процесс-env). Тест T182: с заполненными ids и пустым процесс-env ключ
   приходит из store — `Bearer ` не бывает пустым.
3. **[critical → открытый вопрос] Device flow без exchange** — НЕ реализовано
   намеренно: paste кладётся в `access_token`. Спека R-AUTH-3 требует URL+code и
   exchange. Нужно решение §8.2, потом код или правка спеки.
4. ~~**[critical] `extra_headers` не реализованы**~~ — **ИСПРАВЛЕНО**.
   `api.lua`: `extra_header_lines(cfg)` — catalog `providers.<id>.extra_headers`
   + user `extra_headers` (user wins по имени, name-sorted вывод), валидация
   CR/LF в имени и значении (anti CRLF-injection). Добавляются после
   adapter-заголовков во всех трёх местах: `http_request`, `list_models_live`,
   `refresh_models_bg`. Тест T180.
5. ~~**[critical] `Shift+Up/Shift+Down` отсутствуют**~~ — **ИСПРАВЛЕНО**.
   `ui.lua handle_special`: `k.shift` на up/down → явное движение курсора
   (`move_cursor_up/down`), без recall и без scroll-edge. На терминалах без
   kitty/modifyOtherKeys Shift+Up неотличим от Up — поведение не хуже прежнего.
6. ~~**[critical] Caret без guard для палитры/login secret**~~ — **ИСПРАВЛЕНО**.
   `ui.lua` paint: каретка гасится при `S.palette_active`, `S.confirmation`,
   `S.ask`, `S.login_secret` (T185 проверяет наличие guard'ов).
7. ~~**[critical] Bedrock stored-credentials мертвы**~~ — **ИСПРАВЛЕНО**.
   `auth.aws_creds(no_network, penv)`: `AWS_PROFILE`/keys из stored `env`
   (через `ctx.provider_env` во всех вызовах адаптера: `header_lines`,
   `models_headers`, `preflight`, `creds_of`). Тест T184: stored
   `AWS_PROFILE=stored-proj` выбирает профиль из `~/.aws/credentials`.
8. ~~**[critical] ADC только `authorized_user`**~~ — **ИСПРАВЛЕНО**.
   `auth.read_adc` возвращает `{service_account = ...}` для
   `service_account`-JSON; `auth.resolve_adc_token` минтит токен через JWT
   RS256 (новая C-примитива `tether.rs256_sign` на vendor'd mbedtls + `b64url_encode`
   в common.lua); `config.api_key` использует её для google-vertex.

## 4. Важные проблемы (major) — СТАТУС

1. ~~`commands.lua:195` cooldown только при `#display == 0`~~ — **ИСПРАВЛЕНО**:
   cooldown по `attempted` независимо от `#display` (T183: native-провайдер не
   бьёт endpoint повторно внутри TTL). Причина ошибки по-прежнему поверхится
   только на пустом display — осознанно: непустой список самодостаточен.
2. ~~`api.lua` models-hctx без `session_id`~~ — **ИСПРАВЛЕНО**: и
   `list_models_live`, и `refresh_models_bg` передают `session_id`,
   `provider_env` в `models_headers` (T181: `x-opencode-session` и extra header
   доезжают до models-запроса opencode). `X-Initiator` на models-запросе
   copilot остаётся `user` (messages нет) — допустимо, но отмечено.
3. `azure-openai.lua:76-83` — `/openai/models` вместо deployments path (вопрос §8.5).
4. `openai.lua:214-217` — Copilot статические заголовки (вопрос §8.4).
5. `amazon-bedrock.lua:65` — non-stream `/converse` (вопрос §8.6).
6. ~~**think vs thinking**~~ — **РЕШЕНО**: канон `thinking · Ns`, спека обновлена.
   Дополнительные restyling-решения владельца применены: `•`-маркер ответов,
   ` ⠴ Working... ` в top rule, футер с ` · `-разделителями и `provider/model`.
7. ~~Temp-файлы~~ — **ЧАСТИЧНО ИСПРАВЛЕНО**: body-файл теперь 0600 через
   `tether.fchmod` (создание → fchmod → запись, как у header-файла); header-файл
   уже 0600. `O_EXCL` (symlink-гонка) и CRLF — CRLF-валидация значений сделана в
   `extra_header_lines`; `O_EXCL` на io.open остаётся (Lua не даёт флагов — нужна
   C-примитива; P2). Неатомарные записи config/auth/cache — P2.
8. Однострочный конфиг fail-closed — вопрос §8.11.
9. Неатомарные записи (tmp+rename) — P2.
10. «byte-for-byte» substring-проверка — P2/P3.
11. `auth.json` `env` никто не пишет — смягчено: поле теперь реально используется
    (T182/T184), но программной записи по-прежнему нет (нужен flow — §8).
12. Процесс: change-запись OpenSpec для правок истории/мыши в `tui` — техдолг;
    turn-feedback tasks 1.2 не проставлен.
