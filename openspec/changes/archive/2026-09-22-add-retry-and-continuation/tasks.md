## 8. Interrupt delivery (added after 7.3 exposed the gap)

- [x] 8.1 In `src/host/main.c` watch stdin while blocking a turn: a non-blocking byte poll that raises an interrupt flag on `0x03` and queues every other byte, an interrupt-aware `tether.sleep` (bounded poll, so it wakes on input and still lasts its duration otherwise), and a libcurl progress callback that aborts an in-flight transfer; expose `tether.abort_requested()` and `tether.clear_abort()`. The flag stays set until `clear_abort()` rather than being read-and-clear, because the same Ctrl+C has to keep aborting the transfer until the turn has actually stopped. Verified in `tests/host_primitives_test.c`: the queued order, the flag reported twice and cleared once, the interrupt waking a sleep (and a quiet sleep still waiting), `clear_abort` dropping a stale flag, and a transfer aborted mid-flight (< 1 s against a server that would stream for 1.2 s, with fewer lines delivered than the server sent)
- [x] 8.2 Drain the queued bytes first in `tether.read_char` / `tether.read_char_nb` so keys typed while a turn blocks reach the input line; verified by the host case that queues bytes through the watch (`a`, `b`, `c` around the interrupt) and takes them back in order, with the `0x03` never replayed as input
- [x] 8.3 In `agent.lua` read the interrupt from the host: a `take_abort()` check at the start of the turn, at the top of each attempt loop, right after a failed attempt, inside the streaming callback and in every slice of the wait, treating it exactly like `abort_requested` (no retry, no `error`, one `aborted` event), and clearing both flags once the abort has been handled; verified by T120 (a host interrupt during the wait stops the loop after its retry notice, emits `aborted` with no error, and leaves the flag clear) and T120/11 (an interrupt raised while the transfer is in flight ends the turn as aborted instead of retrying the transport error)
- [x] 8.4 Report an aborted transfer distinctly in `api.lua`/`retry.lua` (`interrupted by user`, non-retryable, classified from libcurl's callback-abort text before anything else) so a transport abort can never be classified as a retryable connection error; verified by the T15 cases for the aborted transfer (kind `interrupted`, not retryable, distinct message) and for a refused connection (still `connection`, still retryable), plus the T120 fallback case where the flag was already consumed
- [x] 8.5 The TUI needed no new code: `aborted` already appends `⏹ прервано (Ctrl+C)`, clears the pending-retry indicator and drops pending projections, and the queued bytes reach the input line; re-verified by the manual runs in 8.6 (the interrupted row appears with no error banner, and no `!!` failure row is drawn)
- [x] 8.6 Confirm by hand that Ctrl+C aborts a wait: with a refused `base_url` and a 2 s + 4 s backoff, the 0x03 piped in after 2 s ended the run in 3.0 s with `⏹ прервано` and no banner, while the same turn without Ctrl+C ran its three attempts and printed `API failed after 3 attempts: request failed: Could not connect to server`. Also confirmed during a running stream, against a stub that streams a delta per second: with Ctrl+C at 2 s the turn drew three deltas and then `⏹ прервано` (3.0 s), where the same turn without Ctrl+C drew the full nine and never aborted
